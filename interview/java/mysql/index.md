# 索引原理与失效场景

## 题目

> InnoDB 为什么用 B+ 树？聚簇索引和二级索引区别？索引失效的常见场景？

## 核心要点

### 为什么是 B+ 树

- 对比哈希：支持范围查询、排序
- 对比 B 树：非叶节点只存键 → 单页能放更多键、树更矮；叶子链表 → 范围扫描快
- 三层 B+ 树可支撑两千万级数据

### 聚簇 vs 二级索引

- 聚簇索引叶子存整行；二级索引叶子存主键 → 查非索引列需**回表**
- 覆盖索引（`select` 列都在索引中）可免回表；最左前缀原则决定联合索引用法

### 失效场景

- 对索引列做函数/运算、隐式类型转换（varchar 列传数字）
- `like '%xx'` 前缀通配、`or` 连接非索引列、`!=`/`not in` 优化器认为选择性差
