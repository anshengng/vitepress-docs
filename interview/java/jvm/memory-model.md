# JVM 运行时内存区域

## 题目

> JVM 运行时数据区分为哪几块？哪些线程私有、哪些共享？各区域存什么、会抛什么异常？栈帧内部长什么样？对象在堆里如何分配、如何晋升老年代？

## 为什么需要

把 JVM 想成一家餐厅，每类数据都有自己该待的地方：

- **程序计数器** = 服务员手里的订单小票：记着"这桌菜做到第几步"，线程切换回来还能接着做
- **虚拟机栈** = 每个服务员自己的操作台：做一道菜（执行一个方法）摞一层托盘（栈帧），做完撤掉
- **堆** = 后厨公共冷库：所有人的食材（对象实例）都放这里，塞满了报警（OOM）
- **方法区** = 菜谱档案室：每道菜的做法（类信息）只存一份，谁来炒都照同一张图

划分逻辑一句话：**私有的存"执行进度"，共享的存"数据与类信息"**——进度人手一份互不干扰，数据共享一份节省空间。

## 核心要点

### 一、运行时数据区总览（JDK 8+）

```
        ┌──────────────────── JVM 进程 ─────────────────────┐
        │   线程1             线程2             线程3  …     │
        │  ┌───────┐        ┌───────┐        ┌───────┐      │
        │  │   PC  │        │   PC  │        │   PC  │ 线程 │
        │  │ 虚拟机栈│        │ 虚拟机栈│        │ 虚拟机栈│ 私有 │
        │  │本地方法栈        │本地方法栈        │本地方法栈│      │
        │  └───┬───┘        └───┬───┘        └───┬───┘      │
        │      │                │                │          │
        │      ▼                ▼                ▼          │
        │  ┌────────────────────────────────────────┐      │
        │  │           堆 Heap（线程共享）             │      │
        │  │  ┌────────┬─────────┬────────┬───────┐ │      │
        │  │  │  Eden  │   S0    │   S1   │ 老年代 │ │      │
        │  │  └────────┴─────────┴────────┴───────┘ │      │
        │  │      字符串常量池（JDK7 起在堆中）        │      │
        │  └────────────────────────────────────────┘      │
        │  ┌────────────────────────────────────────┐      │
        │  │  方法区 = 元空间（共享，位于本地内存）      │      │
        │  │  类元信息 / 运行时常量池                  │      │
        │  └────────────────────────────────────────┘      │
        └───────────────────────────────────────────────────┘
      直接内存：不属于运行时数据区，NIO DirectByteBuffer 用，也可能 OOM
```

### 二、各区域一张表：存什么 + 会什么异常

| 区域 | 存什么 | 异常 | 常用参数 |
| --- | --- | --- | --- |
| 程序计数器 | 当前执行的字节码指令地址 | **唯一不会 OOM 的区域**（执行 native 方法时为 undefined） | — |
| 虚拟机栈 | 栈帧：局部变量表、操作数栈等 | `StackOverflowError`（递归过深）；疯狂建线程可致 OOM | `-Xss` |
| 本地方法栈 | native 方法的栈帧 | 同上（HotSpot 中与虚拟机栈合二为一） | `-Xss` |
| 堆 | 对象实例、数组，GC 主战场 | `OutOfMemoryError: Java heap space` | `-Xms` `-Xmx` |
| 方法区（元空间） | 类元信息、运行时常量池 | `OutOfMemoryError: Metaspace`（CGLIB 动态类过多） | `-XX:MaxMetaspaceSize` |

### 三、栈帧结构 + 一个方法的执行演示

栈帧是方法的执行现场：方法调用时入栈，返回时出栈，与生命周期完全同步。

```
┌──────────── 虚拟机栈（一个线程一份）────────────┐
│  ┌──────────────────────────────┐              │
│  │  栈帧：main()                 │ ◄─ 栈底      │
│  ├──────────────────────────────┤              │
│  │  栈帧：add()（正在执行）       │ ◄─ 栈顶      │
│  │  ┌────────────────────────┐  │              │
│  │  │ ① 局部变量表            │  │  仓库：存参数、局部变量 │
│  │  │ ② 操作数栈              │  │  弹跳床：计算的中转站   │
│  │  │ ③ 动态链接              │  │  指向方法区中该方法的符号引用（支撑多态）│
│  │  │ ④ 方法返回地址           │  │  记录回到 main 的哪一行 │
│  │  └────────────────────────┘  │              │
└─────────────────────────────────────────────── │
```

配一个最小演示（能讲出来就是加分项）：

```java
public int add(int a, int b) {
    int sum = a + b;
    return sum;
}
// main 中调用：add(1, 2)
```

```
字节码指令    操作数栈变化     局部变量表
iload_1  →  [1]            a=1, b=2     槽位1的 a 压栈
iload_2  →  [1, 2]                      槽位2的 b 压栈
iadd     →  [3]                         弹2个相加，结果压回
istore_3 →  []             sum=3        栈顶弹出存入槽位3
iload_3  →  [3]                         sum 压栈
ireturn  →  []                          弹出 3 返回，栈帧出栈
```

记忆口诀：**局部变量表是仓库，操作数栈是弹跳床**——数据从仓库搬上弹跳床，算完再搬回仓库或直接返回。

### 四、堆分代与对象流转路径

```
     ┌──────────── 新生代（约 1/3）─────────────┐  ┌──── 老年代（约 2/3）────┐
     │  Eden（8份）    S0（1份）     S1（1份）    │  │                        │
new ─► 对象在这出生   两块轮换    两块轮换       │  │    长期存活的"老人"      │
     └───────┬─────────────────────────┬────────┘  └───────────▲────────────┘
             │                         │                       │
             │ Eden 满 → Minor GC      │                       │
             │ 存活对象复制到 S0/S1     │  年龄 ≥ 15（默认阈值） │
             │ 每熬过一次 GC 年龄 +1 ───┼────── 晋升老年代 ─────►│
             │ S0、S1 来回复制          │                       │
             └─────────────────────────┘                       │
                                    大对象 ────────────────────┘
                                    （超长数组/大字符串，直接进老年代，
                                     免得在 Survivor 之间来回复制）
```

- 新生代内部比例 `Eden : S0 : S1 = 8 : 1 : 1`；新生代 : 老年代默认 1 : 2
- **TLAB**（线程本地分配缓冲）：Eden 里先给每个线程划一小块私有地盘，分配对象不用加锁，用完再申请
- 晋升老年代的方式：年龄到阈值（默认 15）、动态年龄判断、Survivor 放不下、大对象直入
- 为什么用两块 Survivor？**复制后的空间天然连续无碎片**，且存活对象集中在其中一块，另一块可整块清零

### 五、对象的内存布局

```
┌─────────────────────────────────────────────┐
│ 对象头                                       │
│  ├ Mark Word（8B）：hashCode / GC 年龄 / 锁标志位 │
│  └ 类型指针（开压缩后 4B）：指向方法区的类元数据    │
├─────────────────────────────────────────────┤
│ 实例数据：各字段的实际值（同宽度字段排在一起）      │
├─────────────────────────────────────────────┤
│ 对齐填充：补齐到 8 的整数倍（不足才有这段）        │
└─────────────────────────────────────────────┘
```

- Mark Word 一物多用：synchronized 锁升级的标志位、GC 分代年龄都存在这 8 个字节里
- `new Object()` 没有实例数据，整对象 = 对象头 + 填充 = 16 字节

### 六、永久代 → 元空间、字符串常量池、直接内存

| 事项 | 一句话说明 |
| --- | --- |
| 永久代（JDK7 前） | HotSpot 对方法区的实现，位于**堆内**，大小靠 `-XX:MaxPermSize` 拍脑袋定；框架动态生成类一多就 `PermGen space OOM`，难调优 |
| 元空间（JDK8 起） | 方法区的新实现，改用**本地内存**，默认只受物理内存限制，从根上解决"类数据挤占堆 + 难以预估"的问题 |
| 字符串常量池 | JDK7 起从永久代挪到**堆**中，`intern()` 返回堆内引用，无用的常量也能被正常 GC |
| 直接内存 | 不属于运行时数据区；NIO 的 `DirectByteBuffer` 在堆外分配，省一次堆内外复制；受 `-XX:MaxDirectMemorySize` 限制，也可能 OOM |

## 面试答法

### 30 秒版（可背诵）

> JVM 运行时数据区一共五块：程序计数器、虚拟机栈、本地方法栈是线程私有的，堆和方法区是线程共享的。程序计数器记录当前字节码执行位置，是唯一不会 OOM 的区域；虚拟机栈存栈帧，栈帧里有局部变量表和操作数栈，递归太深会 StackOverflowError；堆放对象实例，是 GC 主战场，满了就堆 OOM；方法区存类信息，JDK8 之后用元空间实现，放在本地内存里，解决了永久代大小难调、容易 OOM 的问题。对象一般在 Eden 创建，Minor GC 后进 Survivor，年龄到 15 晋升老年代，大对象直接进老年代。

### 深入版（编号答题线索）

1. **先分类**：私有（PC / 虚拟机栈 / 本地方法栈）与共享（堆 / 方法区），点出"进度私有、数据共享"的设计逻辑
2. **过异常**：PC 唯一不 OOM、栈 SOE、堆 OOM、元空间 OOM 四个高频考点各一句
3. **栈帧深挖**：画四个部件，用 `add(1,2)` 演示"仓库与弹跳床"的字节码执行过程
4. **堆深挖**：Eden:Survivor 8:1:1、对象流转箭头图、TLAB、大对象直入、年龄晋升、为什么要两块 Survivor
5. **对象布局**：Mark Word / 类型指针 / 实例数据 / 对齐填充，带出锁升级伏笔
6. **收尾元空间**：JDK8 用元空间替换永久代的原因——在本地内存、易扩展、不挤占堆

### 常见追问

- **程序计数器为什么必须有？** → 线程切换后要能恢复到正确的执行位置；执行 native 方法时为 undefined
- **栈是不是越大越好？** → 不是：总内存有限，单线程栈越大，能创建的线程数就越少
- **Metaspace OOM 怎么排查？** → 通常是动态代理/脚本引擎/热部署导致类加载泄漏，`-XX:MaxMetaspaceSize` 兜底 + 排查 ClassLoader
- **对象一定分配在堆上吗？** → 不一定：逃逸分析判定不逃逸的对象可栈上分配或标量替换，减少 GC 压力
- **新生代为什么设计两块 Survivor？** → 一块收存活对象、一块腾空待命，复制后空间连续无碎片，也避免存活对象和 Eden 新对象混放
