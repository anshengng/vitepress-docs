# 分布式事务方案

## 题目

> CAP/BASE 是什么？常见的分布式事务方案有哪些，如何选型？

## 核心要点

### 理论基础

- **CAP**：一致性/可用性/分区容错，P 必选 → CP（ZK、etcd）或 AP（Eureka）
- **BASE**：基本可用 + 软状态 + 最终一致，是对 C 的妥协

### 常见方案

| 方案 | 原理 | 适用 |
| --- | --- | --- |
| 2PC/TCC | 预提交+确认 / Try-Confirm-Cancel | 强一致、金融场景（侵入大） |
| 可靠消息最终一致 | MQ 半消息 + 本地事务 + 回查 | 异步解耦，主流 |
| 最大努力通知 | 定时重试通知 + 对账 | 跨企业对接（支付回调） |
| Seata AT | 全局锁 + undo_log 自动补偿 | 微服务内部，低侵入 |

- 选型思路：能异步就消息最终一致；强一致才考虑 TCC/Seata
