# MQ 高可用与消息积压

## 题目

> Kafka/RocketMQ 的高可用架构是怎样的？线上出现消息积压怎么处理？

## 核心要点

### 高可用

- **Kafka**：多 Broker + 分区多副本，Controller 基于 ZK/KRaft 选 Leader；ISR 机制，Leader 挂了从 ISR 选举
- **RocketMQ**：NameServer 无状态集群，Broker 主从（DLedger 自动切换），同步/异步双写
- 生产/消费端：客户端缓存元数据 + 自动重连、故障转移

### 消息积压处理

1. 先定位：消费逻辑慢？消费者挂了？流量暴涨？
2. 紧急扩容：消费者数 ≤ 分区/队列数，**先扩分区再扩消费者**
3. 临时旁路：新建临时 Topic + 多消费者转发，原逻辑简化后批量落库
4. 事后：消费端优化（批量处理、异步化）、监控 lag 告警
