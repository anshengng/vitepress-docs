# 消息不丢失、不重复、顺序消费

## 题目

> MQ 如何保证消息不丢、不重复消费？如何保证顺序消费？

## 核心要点

### 不丢失（三段把关）

| 环节 | 手段 |
| --- | --- |
| 生产 → Broker | 同步发送 + ack 确认、失败重试（Kafka `acks=all`） |
| Broker 存储 | 持久化（刷盘）、多副本（Kafka replication、RocketMQ 主从） |
| Broker → 消费者 | 手动 ack：业务处理成功后再确认；失败进重试队列/死信队列 |

### 不重复（幂等消费）

- MQ 只保证 at-least-once，重复不可避免 → **消费端幂等**：
  - 唯一业务键 + 数据库唯一索引
  - Redis setnx 记录已处理 msgId
  - 状态机校验（只允许合法流转）

### 顺序消费

- Kafka：同一 key 路由到同一分区，分区内有序；消费端单线程处理该分区
- RocketMQ：MessageQueueSelector 按业务键选队列 + 队列内加锁消费
