# 缓存与数据库一致性

## 题目

> 更新数据时如何保证 Redis 缓存与 MySQL 的一致性？先删缓存还是先更新数据库？

## 核心要点

### 常见策略对比

| 策略 | 问题 |
| --- | --- |
| 先删缓存再更新库 | 删成功后并发读把旧值回填缓存 → 不一致 |
| 先更新库再删缓存 | 主从延迟/删除失败 → 不一致（推荐 + 补偿） |
| 更新库再更新缓存 | 并发写顺序错乱、浪费计算 |

### 推荐方案：Cache Aside + 补偿

1. 先更新数据库，再删除缓存
2. 删除失败 → 消息队列重试 / 订阅 binlog（Canal）异步删缓存
3. 兜底：缓存设置过期时间，最终一致

### 进阶

- 延迟双删：更新库后延迟再删一次缓存，覆盖并发回填
- 强一致场景：读写都走数据库 + 分布式锁，或不用缓存
