# 接口与抽象类、Java 值传递

## 题目

> 接口和抽象类有什么区别？什么时候用哪个？JDK8 接口有了 default 方法，它和抽象类还有区别吗？Java 是值传递还是引用传递？

## 为什么需要

抽象类和接口都是"逼子类实现规范"的手段，但设计意图不同：

```
抽象类：回答 "是什么"（is-a）              接口：回答 "能做什么"（can-do）

   抽象类 Animal                     接口  Comparable /  Serializable
   ├── 字段：name, age（有状态）        ├── 无状态，只有行为契约
   ├── 普通方法：eat()（可给实现）        ├── JDK8+：default/static 方法
   ├── 抽象方法：makeSound()           └── 常量：public static final

   Dog ──is a──► Animal              String、Dog 都 can compare
  （狗是一种动物，天然的血缘）           （不相关的类也能实现同一契约）
```

## 核心要点

### 语法对比表

| 对比项 | 抽象类 | 接口 |
| --- | --- | --- |
| 方法 | 可有普通方法 + 抽象方法 | 抽象方法 + default/static 方法（JDK8）+ private（JDK9） |
| 成员变量 | 任意（可实例字段，有状态） | 只能 `public static final` 常量（无状态） |
| 构造器 | 有（供子类 super 初始化） | 没有 |
| 继承 | 单继承（一个类只能 extends 一个） | 多实现（可 implements 多个） |
| 访问修饰 | 方法任意 | 抽象方法默认 public |

**本质一句话**：抽象类是"模板"（抽出公共部分+留钩子），接口是"契约"（约定能做什么，不关心你是谁）。选型：**有公共状态/公共实现用抽象类，定义能力/规范用接口**。接口解耦更彻底（调用方只依赖契约不依赖实现），所以"面向接口编程"是主流口号。

### JDK8 default 方法之后，接口还是不等于抽象类

关键差异：**接口无法携带实例状态**（没有实例字段、没有构造器做初始化），default 方法只能在"无状态"的前提下给默认实现。抽象类能存字段、能写构造器、能保护部分实现不被无关类复用——这是接口永远替代不了的。

```
一个"抽象类对象"里装得下什么：            一个"接口实现类对象"里，接口贡献的只有方法：

  实例字段 name = "订单服务"                 （接口自己那份：零）
  实例字段 status = RUNNING
  构造器初始化的私有状态                     接口只能提供：
  部分已实现的模板方法 ──► 能读写上面的字段     · static final 常量（全类共享，不是实例状态）
                                           · default 方法 ──► 只能调接口方法/常量，摸不到实例字段
                                           · static 方法（工具性质）

  → 抽象类 = "带着状态的半成品"             → 接口 = "不带状态的纯契约"
```

典型对照：`AbstractList` 里维护着 `modCount` 字段并实时更新（有状态模板）；
`List.sort()` 是 default 方法，只能依赖 `size()/get()/set()` 这些接口方法完成排序（无状态编排）。

### 多实现 default 冲突：菱形问题

```
       interface A                 interface B
       default hello()              default hello()
       { 打印 "A" }                  { 打印 "B" }
              \                     /
               \                   /
                class C implements A, B   ← 两个同名 default，编译器报错：
                                          "继承了不相关的默认方法"
```

解决规则：

1. **类优先**：父类/自己定义的同名方法，优先于接口的 default
2. **两个接口冲突**：必须**显式重写**，可用 `A.super.hello()` 指定调谁：

```java
class C implements A, B {
    public void hello() { A.super.hello(); } // 明确选 A 的版本
}
```

### 经典题：Java 只有值传递

Java **永远传"值的拷贝"**——基本类型拷贝值，引用类型拷贝"地址值"。区别只是：拷贝的是内容，还是地址。

```
【实验一】方法内改引用指向 → 不影响外部

调用 change(s) 前后，main 栈帧 和 change 栈帧各自持有引用：

   main 栈帧              change 栈帧
   sb ────┐               sb' ────┐      ← 传入时：复制一份地址给 sb'
          ▼                       │
        堆 [ "hi" ] ◄─────────────┘      两个引用指向同一个对象

   change 里执行 sb' = new StringBuilder("xx");
   main: sb ────► 堆["hi"]   ← sb' 玩自己的去了，sb 毫发无损
   change: sb' ──► 堆["xx"]   （改的是 change 栈帧里那份"地址拷贝"）
   → 方法返回后 main 打印 sb，还是 "hi"  ✗ 改指向无效

【实验二】方法内改对象内部 → 影响外部

   同样传地址拷贝，但执行的是 sb'.append("!")：

   main: sb ────┐
   change: sb' ──┼──► 堆 [ "hi" → "hi!" ]  ← 同一个对象被改了内容
                ┘
   → main 打印 sb，变成 "hi!"  ✓ 改内容有效
```

一句话：**传引用的"地址副本"**。所以 Java 没有引用传递（C++ 的 `int&` 那种能改外部变量本身的效果，Java 做不到）。

## 面试答法

### 30 秒版（可背诵）

> 抽象类和接口的核心区别是设计意图：抽象类是"是什么"，抽取公共状态和实现，是代码复用的模板；接口是"能做什么"，定义行为契约，让不相关的类都能实现。语法上抽象类有字段和构造器、单继承，接口只有常量、可以多实现。JDK8 接口加了 default 方法，但因为接口没有实例字段、带不了状态，还是替代不了抽象类。至于值传递：Java 只有值传递，传的是拷贝——基本类型拷贝值，对象拷贝地址，所以方法里改引用指向不影响外面，改对象内容才会影响外面。

### 深入版（被追问时按编号展开）

1. **语法差异**：对比表过一遍（方法/字段/构造器/单继承 vs 多实现）
2. **本质区别**：is-a 模板 vs can-do 契约，画两个类图；选型原则（公共状态用抽象类，能力规范用接口）
3. **default 时代**：接口仍无状态；多实现冲突的两个规则（类优先、冲突必重写 + `A.super.xxx()`）
4. **值传递**：两组对比图——改指向 vs 改内容，强调"传的是地址的拷贝"

### 常见追问

- **接口能定义 main 方法吗？** → 能，static 方法，JDK8 起
- **抽象类可以没有抽象方法吗？** → 可以（比如只想禁止被实例化）；有抽象方法的类必须声明为抽象类
- **default 方法的意义？** → 接口演进不破坏实现类（如 Collection 加 stream()），老实现类不用改
- **String 传参在方法里改了，外面为什么不变？** → 不可变 + 值传递，方法内拿到的地址拷贝指向新对象，外面的引用没动
