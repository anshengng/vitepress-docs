# v-if 和 v-show 的区别

## 为什么需要

两者都能"控制元素显示与否"，但实现机制完全不同：一个操作**DOM 的存在**，一个操作 **CSS 的 display**。选错会影响性能（频繁切换用 v-if 会反复销毁重建）、生命周期（v-if 会触发挂载/卸载，v-show 不会）、以及初始渲染成本。面试考察点：是否理解"条件渲染 vs 条件显示"的本质差异，能否按切换频率、初始开销、是否含组件状态来选型。

## 核心要点

### 1. 本质机制对比

```
v-if 条件为 false：
  DOM 树里【根本没有】这个节点
  <div id="app">
    <!-- 注释占位（vue2）/ 直接不存在（vue3） -->
  </div>

v-show 条件为 false：
  节点【已渲染】在 DOM 里，只是被 CSS 藏起来
  <div style="display: none;">我还是在 DOM 里</div>
```

| 维度 | v-if | v-show |
| --- | --- | --- |
| 实现方式 | 真正条件渲染：销毁/重建 DOM 与组件实例 | CSS 切换：`display: none / ''` |
| 切换开销 | **高**（销毁重建、触发生命周期） | **低**（只改一个样式） |
| 初始渲染开销 | 低（false 时压根不渲染） | 高（无论如何都渲染一次） |
| 生命周期 | 条件变化触发 mounted / unmounted，组件状态丢失 | 组件一直存活，状态保留 |
| 惰性 | 有（初始条件为假则不渲染，惰性求值） | 无（初始即渲染） |
| 与 transition 配合 | 可包 `<Transition>`，进出场靠渲染时机 | 可配合，但切换瞬间无插入/移除过程 |
| 适用场景 | 不常切换、初始可能不渲染（权限位、路由级块） | 频繁切换（tab 面板、下拉显隐） |

### 2. 选型口诀（按切换频率 + 初始成本决策）

```
频繁切换？
  ├─ 是 ──► v-show（改 CSS 便宜，重建 DOM 贵）
  └─ 否 ──► 初始大概率不显示？
              ├─ 是 ──► v-if（省掉首屏渲染和组件初始化）
              └─ 否 ──► 两者皆可，团队统一
```

### 3. 配套语法与常见坑

```html
<!-- v-if 支持 else / else-if 链；v-show 没有 -->
<p v-if="type === 'a'">A</p>
<p v-else-if="type === 'b'">B</p>
<p v-else>其他</p>

<!-- 多元素用 template 包裹（template 不会渲染成真实节点） -->
<template v-if="ok">
  <h1>Title</h1>
  <p>Paragraph 1</p>
</template>
```

```html
<!-- 坑：v-if 和 v-show 不要与 v-for 同级混用 -->
<!-- Vue3：v-if 优先级【高于】v-for，此时 item 未定义，直接报错 -->
<li v-for="item in list" v-if="item.show"></li>
<!-- 正确：用 computed 先过滤 -->
<li v-for="item in visibleList" :key="item.id"></li>
```

## 面试答法

### 30 秒版本（可直接背诵）

> v-if 是真正的条件渲染：条件为假时 DOM 里根本没有这个节点，切换时组件会销毁重建，走完整的挂载卸载生命周期；v-show 只是把 CSS 的 display 切成 none，节点始终渲染并保留在 DOM 中，内部状态也不丢。所以频繁切换用 v-show 更划算，只改样式不重建 DOM；初始可能不显示、或切换很少的内容用 v-if，能省掉首屏渲染成本。另外 v-if 支持 v-else、v-else-if 和 template 包裹，v-show 不支持；两者都不要和 v-for 写同级，Vue3 里 v-if 优先级更高会拿不到循环变量，应该用计算属性先过滤。

### 深入展开

1. **先讲机制**：v-if 编译成条件判断 + 占位节点，运行时插入/移除；v-show 编译成 `vShow` 指令，只 patch `style.display`
2. **开销模型**：DOM 创建/销毁 + 子组件实例化是昂贵操作（触发响应式建立、生命周期钩子），而改一个内联样式几乎零成本
3. **生命周期差异**：v-if 反复切换时组件内部 data 会被重置——这是"状态丢失"事故来源；v-show 保状态
4. **惰性价值**：v-if 初始为假就不渲染，对首屏有大数据表格/富组件很有用；v-show 无此能力
5. **延伸**：需要"缓存组件状态又不重建"时，用 `<keep-alive>` 而非 v-show（keep-alive 卸载但缓存实例，v-show 是不卸载）

### 常见追问

- **v-if 切换时组件状态会丢吗？** → 会，实例被销毁重建，内部 state 全部重置；要保留状态用 v-show 或 keep-alive
- **v-if 和 v-show 哪个初始渲染快？** → 条件为假时 v-if 快（压根不渲染），v-show 必须完整渲染一次再藏起来
- **为什么 v-show 不能配合 v-else？** → v-else 依赖"上一个条件分支不渲染"的编译结构，v-show 永远渲染，没有 else 语义可言
- **v-for 和 v-if 优先级？** → Vue2 中 v-for 优先（v-if 在每项循环内求值，浪费）；Vue3 中 v-if 优先（拿不到 item，禁止同级使用）
- **什么时候用 keep-alive 而不是 v-show？** → 组件需要"移出视图但保留实例和 DOM 缓存"（如列表↔详情返回不重新请求），v-show 只是 CSS 隐藏，组件始终在视图树里占着渲染成本
