# HTTP 状态码体系

## 题目

> 状态码怎么分类？301、302、307、308 有什么区别？304 是重定向吗？401 和 403 什么时候出现？502 和 504 怎么区分？404 和 410 呢？前端拦截器里该怎么按状态码分流？

## 为什么需要

状态码是 HTTP 的"契约语言"：**首位数字直接判定锅在哪一侧**——2xx 我干成了，3xx 你得换个地方拿，4xx 你的请求有问题，5xx 我这边出故障了。面试不要求背全所有码，但必须给出分类框架，并讲清几组高频易混对：301/302/307/308、304（它根本不是重定向）、401/403、502/504。

## 核心要点

### 1. 按首位分类

| 类别 | 含义 | 一句话理解 | 代表 |
| --- | --- | --- | --- |
| 1xx | 信息 | 请求收到了，继续处理 | 100 Continue、101 切换协议 |
| 2xx | 成功 | 请求目标已达成 | 200、201、204 |
| 3xx | 重定向 | 要再做一步才能拿到 | 301、302、304、307、308 |
| 4xx | 客户端错误 | **你的**请求有问题 | 400、401、403、404、405、408、413、429 |
| 5xx | 服务端错误 | **我的**这边出问题了 | 500、502、503、504 |

### 2. 300 段：重定向 vs 条件缓存（最易混）

```
301 Moved Permanently（永久）：
浏览器 ──GET /old──► 服务器：301 + Location: /new
      └─ 改地址栏，且【浏览器永久缓存】这条映射，
        以后直接请求 /new，不再问 /old；搜索引擎转移权重

302 Found（临时）：
浏览器 ──GET /page──► 服务器：302 + Location: /login
      └─ 这次去 /login，下次仍然先请求 /page（不缓存映射）

307 / 308（302 / 301 的"严格版"）：方法与 body 原样保留
POST /order ──307──► 仍然 POST /new-order，body 不变
（301/302 历史上会被部分实现"改成 GET 再重放"，307/308 堵死这个口子）

303 See Other：POST 之后重定向到结果页 → 刷新不再重复提交（PRG 模式）

304 Not Modified：根本不是重定向！
浏览器 ──GET /app.js + If-None-Match: "abc"──► 服务器：304（无 body）
      └─ "你本地那份没变，继续用缓存" → 省的是响应体带宽
```

| 码 | 永久/临时 | 方法保留？ | 本质 |
| --- | --- | --- | --- |
| 301 | 永久（被缓存） | 常被改为 GET | 资源搬家 |
| 302 | 临时 | 常被改为 GET | 临时改道 |
| 303 | 临时 | 强制改 GET | POST 后跳结果页 |
| 307 | 临时 | ✅ 严格保留 | 不撒谎的 302 |
| 308 | 永久 | ✅ 严格保留 | 不撒谎的 301 |
| 304 | — | — | 缓存协商命中，非重定向 |

### 3. 400 段速查（面经列全的都要能说出场景）

| 码 | 名称 | 典型触发场景 |
| --- | --- | --- |
| 400 | Bad Request | 参数缺失/格式错、JSON 语法错误 |
| 401 | Unauthorized | 未认证：没带 token 或 token 过期（响应带 `WWW-Authenticate`） |
| 402 | Payment Required | 协议保留，几乎不用 |
| 403 | Forbidden | 已认证但权限不足，重试也没用 |
| 404 | Not Found | 资源不存在（路径写错/接口没发布） |
| 405 | Method Not Allowed | 方法不对（响应带 `Allow` 头列出可用方法） |
| 406 | Not Acceptable | 服务器给不出 `Accept` 要求的格式 |
| 407 | Proxy Authentication Required | 需要先过代理认证 |
| 408 | Request Timeout | 客户端发得太慢，服务端等超时主动断开 |
| 409 | Conflict | 状态冲突：并发编辑、重复注册 |
| 410 | Gone | 资源曾存在、已永久删除（比 404 更"确定"，利于 SEO 下架） |
| 411 | Length Required | 缺 `Content-Length`（chunked 场景） |
| 412 | Precondition Failed | `If-Match`/`If-Unmodified-Since` 条件不成立 |
| 413 | Payload Too Large | body 超过服务端限制（Nginx `client_max_body_size`） |
| 414 | URI Too Long | 请求行超长（把大参数塞进 GET 查询串） |
| 415 | Unsupported Media Type | `Content-Type` 服务器不接受（该传 JSON 传了 form） |
| 416 | Range Not Satisfiable | Range 越界（断点续传位置超过文件大小） |
| 417 | Expectation Failed | `Expect: 100-continue` 不被满足 |
| 429 | Too Many Requests | 触发限流（响应带 `Retry-After`） |

### 4. 500 段

| 码 | 名称 | 区分要点 |
| --- | --- | --- |
| 500 | Internal Server Error | 应用自身抛未捕获异常，最笼统的服务端错误 |
| 501 | Not Implemented | 服务器压根不支持这个功能/方法 |
| 502 | Bad Gateway | 网关/代理**收到了上游的无效响应**——后端进程挂了、崩溃、返回畸形报文 |
| 503 | Service Unavailable | 过载或维护中，可带 `Retry-After`；LB 摘除全部后端时也常见 |
| 504 | Gateway Timeout | 网关**等上游超时**——后端没挂但太慢（慢 SQL、下游依赖卡死） |

**502 vs 504 口诀**：502 = 后端"回了句疯话"；504 = 后端"没回话"。看到这两个码先查网关日志的 upstream 字段定位。

### 5. 最易混对：401 vs 403

```
401 Unauthorized：「你是谁？」——没出示/出示了无效凭证 → 登录后重试有意义
     响应常带：WWW-Authenticate: Bearer realm="api"
403 Forbidden  ：「知道你是谁，但不行」——身份有效但权限不足 → 重试无用，要换权限

前端拦截器分流（面试常要求现场说）：
  401 → 清 token、跳登录页 / 静默刷新 token 后重放
  403 → 停留当前页，提示"无权限"
  429 → 按 Retry-After 退避重试
  5xx → 提示"服务暂不可用"，指数退避
```

## 面试答法

### 30 秒版（可背诵）

> 状态码按首位分五类：1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误。300 段里 301 永久重定向会被浏览器缓存、利于 SEO 转移权重；302 临时不缓存；307/308 是 302/301 的严格版，重放时保留原方法和 body；303 用于 POST 后跳结果页防重复提交；304 不是重定向，是条件请求命中缓存、服务器让浏览器直接用本地副本。400 段记 401 未认证要重新登录、403 无权限重试没用、404 不存在、405 方法不对、408 客户端发太慢、413 上传超限、429 被限流。500 段重点是 502 网关收到上游无效响应、504 网关等上游超时——一个"回了疯话"一个"没回话"。前端拦截器按 401 跳登录、403 提示无权限、5xx 退避重试分流。

### 深入版（被追问时按编号展开）

1. **先给分类框架**：首位数字=责任归属，再展开具体码
2. **画 301/302 流程**：Location 头 + 是否缓存映射 + 对 SEO 影响
3. **讲 307/308 存在的意义**：301/302 历史实现会把 POST 改成 GET 重放，严格版堵死
4. **纠正 304**：条件请求（If-None-Match）命中，省 body 不省请求，与 ETag 一起讲
5. **401 vs 403**：认证 vs 授权，配前端拦截器分流策略
6. **502 vs 504**：网关视角，"上游回疯话/不回话"，排查方向不同
7. **收尾加分**：PRG 模式（303）、429+Retry-After 限流、410 主动下架利于 SEO

### 常见追问

- **304 算命中缓存还是重定向？** → 缓存命中。响应无 body，浏览器用本地副本；它出现在"协商缓存"环节，不是让你换 URL
- **301 为什么调试时慎用？** → 浏览器会永久缓存 301 映射，服务端改回来浏览器仍直接跳旧目标，出现"怎么都测不对"的鬼现象；调试用 302
- **204 和 200 空 body 的区别？** → 204 明确"无内容且不应改文档"，浏览器不更新页面；常用于 DELETE/PUT 成功回执
- **CORS 预检成功返回什么？** → 通常 204（或 200）无 body，只靠响应头答复；预检失败浏览器直接拦，真实请求根本不发
- **408 和 504 都是超时，区别？** → 408 是服务端等"客户端把请求发完"超时；504 是网关等"上游服务端响应"超时，方向相反
- **状态码能自定义吗？** → 协议上可以（如 599），但网关/SDK 可能不识别；业务错误建议 HTTP 层用 200/4xx，业务码放 body
