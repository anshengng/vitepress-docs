# 什么是垃圾回收机制，有哪几种

## 为什么需要

JS 的内存是自动管理的：不再使用的对象由 GC 回收。理解 GC 才有能力解释**内存泄漏**（闭包不解绑、定时器不清理、detached DOM）为什么发生、GC 停顿为什么会卡页面，以及 WeakMap/WeakRef 存在的意义。面试常考"标记-清除 vs 引用计数"的取舍和分代回收的依据。

## 核心要点

### 1. 基本概念

```
内存分区：
  栈（调用栈）：基本类型值、对象引用、函数执行帧 —— 帧弹出即释放
  堆：对象、数组、闭包作用域等引用类型 —— 由 GC 负责回收

GC 的核心问题：判断堆上哪些对象"再也用不到了"
  主流答案：可达性 —— 从"根"出发走不到的对象就是垃圾
```

### 2. 四种算法对比总表

| 算法 | 核心思想 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 引用计数 | 每个对象记"被引用次数"，归零即回收 | 实时性好，实现直观 | **循环引用无法回收**；计数本身有开销 |
| 标记-清除 | 从根对象遍历标记所有可达对象，清除未标记 | 能处理循环引用 | 清除后留下**内存碎片** |
| 标记-整理 | 标记后把存活对象向一端移动，释放边界外内存 | 无碎片 | 移动对象开销大，需更新所有引用 |
| 分代回收 | 按寿命分年轻代/老年代，各用不同策略 | 效率最高，主流引擎方案 | 实现复杂 |

```
引用计数的死穴——循环引用：

let a = {}; let b = {}
a.ref = b; b.ref = a   // a、b 互相引用，计数各为 2
a = null; b = null     // 外部已不可达，但互相引用计数永不为 0 → 泄漏 ❌
（标记-清除视角：从根出发走不到 a、b → 正确判定为垃圾 ✅）
```

### 3. 可达性图解（标记-清除两阶段）

```
阶段一 标记：从根出发遍历
  根（全局对象、当前调用栈上的变量、活跃闭包）
   ├─► obj1 ✅ 标记存活
   ├─► obj2 ✅ ──► obj3 ✅（引用链传递）
   └─► obj4 ✅
  堆上还有 obj5、obj6 没有任何根能走到 → 未标记

阶段二 清除：释放 obj5、obj6 的内存
（标记-整理则改为：把 obj1~4 挪到一起，截断空闲区）
```

### 4. V8 的分代实践

| 代 | 对象特征 | 算法 | 特点 |
| --- | --- | --- | --- |
| 年轻代 | 朝生夕灭（临时对象、闭包、字面量） | **Scavenger 复制**：from/to 两个半区，存活对象整体复制到 to，交换角色 | 回收频繁但单次快（只动存活少数） |
| 老年代 | 活得久、晋升的对象 | 标记-清除 / 标记-整理 | 回收不频繁、代价大 |

- 晋升规则：在年轻代熬过多轮 Scavenge 的对象搬进老年代
- 优化手段：**增量标记**（把标记切成小步穿插执行）、并行/并发回收——目的都是缩短 GC 停顿，减少页面卡顿

### 5. 常见泄漏场景与排查

```javascript
// ① 闭包/事件不解绑：回调活着，作用域链上的大对象就回收不掉
document.addEventListener('resize', handler) // 组件卸载时 removeEventListener

// ② 遗忘的定时器：setInterval 持有回调 → 持有外部变量
const id = setInterval(fn, 1000) // 用完 clearInterval(id)

// ③ 无上限的缓存 Map：key 强引用对象
const cache = new Map()          // 改用 WeakMap，键可被回收

// ④ 意外全局变量：未声明赋值泄漏到 window
function leak() { huge = new Array(1e7) } // 漏写 let → 永不回收；严格模式可拦截
```

排查：Chrome DevTools → Memory 拍堆快照对比（三次快照法看持续增长对象）、Performance 看 GC 事件。

## 面试答法

### 30 秒版本（可直接背诵）

> 垃圾回收是引擎自动释放"不再使用"的堆内存的机制，避免手动 free 的出错和泄漏。判断垃圾有两条路线：引用计数记每个对象被引用次数、归零回收，实时但处理不了循环引用；主流是可达性分析，从全局、调用栈这些根出发标记可达对象，走不到的就是垃圾。具体算法有标记-清除（简单但有碎片）、标记-整理（移动存活对象消除碎片）、以及工程上真正用的分代回收：年轻代对象多短命，用复制算法高频小步回收；老年代低频用标记清除/整理，V8 再加增量标记来缩短停顿。开发者要配套注意闭包不解绑、定时器不清理、无上限缓存这些泄漏源。

### 深入展开

1. **先定位内存模型**：栈自动弹帧、堆靠 GC，GC 只管堆
2. **两条判断路线**：引用计数（画循环引用死局图）vs 可达性（画根遍历图）
3. **算法逐个讲**：标记-清除 → 碎片问题 → 标记-整理 → 移动开销 → 分代 → 弱分代假说
4. **V8 落地**：Scavenger 半区复制、晋升、老年代标记整理、增量/并发降停顿
5. **泄漏四件套**：事件、定时器、闭包链、全局变量 + WeakMap 对策
6. **收尾**：DevTools 堆快照排查思路，体现工程经验

### 常见追问

- **为什么引用计数被主流引擎弃用？** → 循环引用永远回收不掉，且每次赋值/传参都要维护计数，开销大
- **循环引用在标记-清除下会泄漏吗？** → 不会，从根不可达就被清除；只有引用计数算法怕它
- **分代回收的理论依据？** → 弱分代假说：绝大多数对象朝生夕灭，活过几轮的对象往往活得久
- **年轻代为什么用复制算法？** → 存活对象少，"只搬活的"成本低于"扫全部"，且天然整理无碎片；代价是要预留一半空间
- **GC 停顿为什么会卡页面？** → 回收和 JS 共用主线程，标记阶段过长会挤压渲染帧；增量标记把长任务切片缓解
- **WeakMap 键为什么能被回收？** → 弱引用不增加可达性计数，外部强引用消失后键连同值整体回收
