# img 标签的 alt、title 代表什么，有什么作用

## 为什么需要

这题表面考两个属性，实际考 **HTML 语义化与无障碍（a11y）** 的意识：图片对"看不见"的用户（屏幕阅读器）和"加载不到"的用户（弱网、图挂了）意味着什么。前端规范要求信息性图片必须有 alt，WCAG 可访问性标准也把缺 alt 列为高频违规项——大厂国际化/政务/金融项目都会用 Lighthouse 强制检查。

## 核心要点

### 1. alt：替代文本（alternative text）

作用时机与场景：

```
正常显示        图片加载失败/禁用图片       屏幕阅读器
 ┌────────┐      ┌──────────────┐         🔊 "商品主图：
 │  图片   │  →   │ 商品主图：白色 │    →     白色运动鞋"
 └────────┘      │  运动鞋"（文字）┘         （朗读 alt）
                 └──────────────┘
```

- **加载失败兜底**：显示 alt 文字，用户仍知道这里本来是什么。
- **无障碍**：屏幕阅读器把 alt 作为图片的"名字"朗读；alt 缺失时部分读屏会朗读文件名（如 `IMG_2333.png`），体验灾难。
- **SEO**：搜索引擎靠 alt 理解图片内容，图片搜索排名的主要依据。
- **禁用图片的浏览器/慢网**：占位提示。

三种写法的选择：

```html
<!-- ① 信息性图片：alt 写清含义 -->
<img src="chart.png" alt="2024 年 Q1-Q4 销售额逐季增长柱状图">

<!-- ② 装饰性图片：空 alt（读屏直接跳过） -->
<img src="bg-divider.png" alt="">

<!-- ③ 省略 alt 属性：最差——读屏可能朗读文件名，SEO 也丢分 -->
<img src="bg-divider.png">
```

> 关键细节：装饰图用 `alt=""` 而**不是不写 alt**。`alt=""` 显式告诉读屏"忽略我"；不写则被当作"缺失替代文本"。

### 2. title：附加提示（tooltip）

- 鼠标**悬停**一段时间后，浏览器原生弹出小提示框，用于补充说明。
- **不是 alt 的替代品**：屏幕阅读器默认不朗读 title；触屏设备根本没有 hover，title 不可达；提示出现有延迟、无法定制样式、无法键盘触发。
- 对 SEO 基本无权重作用。

### 3. alt vs title 对比表

| 维度 | alt | title |
| --- | --- | --- |
| 语义定位 | 图片的**替代文本**（图片没了它顶上） | **补充提示**（锦上添花） |
| 加载失败时 | ✅ 显示 alt 文字 | ❌ 无关 |
| 屏幕阅读器 | ✅ 朗读（无障碍必需） | ❌ 默认不读 |
| 触屏设备 | 不涉及显示，但读屏可用 | ❌ 无 hover，不可达 |
| SEO | ✅ 图片搜索主要依据 | 几乎无作用 |
| 是否必填 | 信息图必填，装饰图填 `""` | 可省略 |
| 悬停显示 | ❌（仅图挂时显示） | ✅ tooltip |

### 4. 相关加分项

```html
<!-- 复杂图表：figcaption 提供长描述，比 title 语义化 -->
<figure>
  <img src="chart.png" alt="销售额柱状图">
  <figcaption>Q1 120 万，Q2 150 万……同比增长 25%</figcaption>
</figure>

<!-- 图片是链接内容时（如 logo 跳首页），alt 必填且描述"用途"而非"内容" -->
<a href="/"><img src="logo.svg" alt="返回首页"></a>
```

- 无障碍进阶：`aria-label` / `aria-labelledby` 可覆盖 alt；`role="presentation"` 也可标记装饰图。
- Lighthouse / axe 检测项 "image-alt" 即来源于此。

## 面试答法

### 30 秒版本（可直接背诵）

> alt 是替代文本：图片加载失败时显示、屏幕阅读器朗读、搜索引擎理解图片内容的依据，信息性图片必须写，装饰性图片写空字符串 alt="" 而不是省略。title 是悬停提示框，只做补充说明，屏幕阅读器不读、触屏没有 hover 所以不可达，不能当 alt 用。一句话总结：alt 面向"看不到图片"的场景，是语义和无障碍的一部分；title 面向"鼠标悬停"的场景，是可选的增强提示。

### 深入展开

1. **按"三种用户"讲 alt**：正常用户（加载失败兜底）、视障用户（读屏朗读）、爬虫（图片 SEO）。
2. **讲 `alt=""` 与省略 alt 的区别**——这是区分"背过"和"懂无障碍"的细节。
3. **讲 title 的三大缺陷**：读屏不读、触屏不可达、样式/时机不可控。
4. **延伸语义化**：figure/figcaption 承载长描述；链接内图片的 alt 写用途。
5. **落地标准**：WCAG 1.1.1 Non-text Content 是 P1 级要求，Lighthouse 可直接演示。

### 常见追问

- **装饰图为什么不直接删掉 img？** → 视觉上是需要的，只是对内容无信息量，用 `alt=""` 让读屏跳过即可。
- **alt 和 aria-label 冲突时谁生效？** → 对 img，aria-label 优先级更高、会覆盖 alt；但一般建议只用 alt，兼容性最好。
- **title 属性能用在哪些元素？** → 全局属性，任何元素都可加悬停提示；但同样存在不可达问题，交互提示应自定义 tooltip（focus/hover 双触发、可键盘访问）。
- **图片懒加载和 alt 有关系吗？** → 无关但常一起考：懒加载用 `loading="lazy"`，占位期 alt 正好提供兜底文案。
- **背景图（CSS background）怎么做无障碍？** → 背景图对读屏和爬虫完全不可见，有信息量的图必须用 img + alt，纯装饰才放 CSS。
