# Webpack loader 与 plugin 开发

loader 和 plugin 是 Webpack 的两个扩展面：**loader 加工"单个模块的内容"**（把任意文件变成 JS），**plugin 干预"整个构建流程"**（订阅钩子、增删产物）。生命周期与 tapable 钩子体系见 [Webpack 底层原理（编译流程）](/notes/webpack/architecture-flow)，本页只讲怎么写。

## loader 开发

### 签名与执行模型

loader 是一个函数，`this` 指向 LoaderContext（由 Webpack 注入）：

```js
module.exports = function (content, sourceMap, meta) {
  // content   ：源文件内容，默认 UTF-8 字符串；加 raw 标记后是 Buffer
  // sourceMap ：上游 loader 传来的 map（可选）
  // meta      ：跨 loader 传递的元数据对象
  // this.query      ：loader 选项（字符串/对象）
  // this.getOptions()：带 schema 校验的选项解析（webpack5 推荐）
  // this.callback   ：异步返回（err, content, map, meta）
  // this.async()    ：拿到 callback，声明本 loader 是异步的
  // return          ：同步返回新内容
}
```

两种返回方式二选一：同步直接 `return`；异步调用 `this.async()` 拿 callback（用了 callback 就不能再 return）。

### pitching 阶段与执行顺序

一条规则链配置了多个 loader 时，执行分两个阶段：

```
use: ['a-loader', 'b-loader', 'c-loader']

pitching 阶段（从左到右）：  a → b → c
normal  阶段（从右到左）：  c → b → a

完整时序：a(pitch) → b(pitch) → c(pitch) → c(normal) → b(normal) → a(normal)
```

pitching 的短路规则：某个 loader 的 pitch 函数**返回了非 undefined 值**，则跳过它后面所有 loader（pitch 与 normal 都不跑），直接进入已执行过 loader 的 normal 阶段回退。`style-loader` 正是靠 pitch 短路：它发现链尾是 CSS 时，直接返回一段"把 css-loader 结果内联进 JS"的代码，让 css-loader 的产物不再作为模块继续解析。

pitch 写法（loader 函数挂属性）：

```js
function myLoader(content) { return content }
myLoader.pitch = function (remainingRequest, precedingRequest, data) {
  // remainingRequest：链上剩余 loader 的请求串
}
module.exports = myLoader
```

### 示例一：code-banner loader（同步）

给匹配到的文件头部注入一行注释：

```js
// loaders/banner-loader.js
module.exports = function (content) {
  // webpack5 内置选项解析，无需 loader-utils
  const options = this.getOptions()
  const text = options.text || 'generated by webpack'
  return `/* ${text} */\n${content}`
}

// webpack.config.js
{
  test: /\.js$/,
  use: {
    loader: path.resolve('loaders/banner-loader.js'),
    options: { text: 'banner-loader 示例' }
  }
}
```

### 示例二：markdown→html loader（异步）

演示 `this.async()` 与 sourcemap 传递（真实项目里用 marked 等库解析，这里只展示管线写法）：

```js
// loaders/md-loader.js
module.exports = function (content) {
  const callback = this.async()   // 声明异步，拿到完成回调

  // 模拟异步处理（如调用解析库、读额外文件）
  setTimeout(() => {
    const html = content
      .replace(/^### (.*)$/gm, '<h3>$1</h3>')
      .replace(/^## (.*)$/gm, '<h2>$1</h2>')
      .replace(/\n\n/g, '\n')
    // 输出 JS 模块：导出字符串，供 vue-loader / 业务代码 import
    callback(null, `export default ${JSON.stringify(html)}`)
  }, 0)
}
```

要点：输出必须是 **JS 代码或可被后续 loader 处理的格式**；`test` 匹配什么就处理什么，链上顺序决定谁先拿到原始内容。

## plugin 开发

### 基本骨架

插件是带 `apply(compiler)` 方法的类，在 `apply` 里订阅钩子（钩子语义见[底层原理页](/notes/webpack/architecture-flow)）：

```js
class MyPlugin {
  constructor(options = {}) { this.options = options }
  apply(compiler) {
    compiler.hooks.done.tap('MyPlugin', () => {
      console.log('构建结束')
    })
  }
}

// webpack.config.js
plugins: [new MyPlugin({ /* ... */ })]
```

注意 `webpack.config.js` 里是 `new` 出来的**实例**，而 loader 配置里写的是**函数本身**——这是两者注册形态的差异。

### 示例一：产物体积报告插件

在写盘后遍历 `compilation.assets`，按体积排序打印：

```js
// plugins/size-report-plugin.js
class SizeReportPlugin {
  apply(compiler) {
    compiler.hooks.afterEmit.tap('SizeReportPlugin', (compilation) => {
      const rows = Object.entries(compilation.assets)
        .map(([name, asset]) => ({ name, size: asset.size() }))
        .sort((a, b) => b.size - a.size)

      console.log('\n=== 产物体积报告 ===')
      for (const { name, size } of rows) {
        console.log(`${(size / 1024).toFixed(1).padStart(8)} KB  ${name}`)
      }
    })
  }
}
module.exports = SizeReportPlugin
```

### 示例二：注入构建时间插件

在 `processAssets` 阶段凭空加一个产物文件，演示 `RawSource` 与 stage 用法：

```js
// plugins/build-time-plugin.js
class BuildTimePlugin {
  apply(compiler) {
    const { Compilation, sources } = compiler.webpack   // webpack5 推荐从 compiler.webpack 取

    compiler.hooks.thisCompilation.tap('BuildTimePlugin', (compilation) => {
      compilation.hooks.processAssets.tap(
        {
          name: 'BuildTimePlugin',
          stage: Compilation.PROCESS_ASSETS_STAGE_ADDITIONS   // 产物追加阶段
        },
        () => {
          const info = JSON.stringify({
            builtAt: new Date().toISOString(),
            hash: compilation.hash
          })
          compilation.emitAsset(
            'build-info.json',
            new sources.RawSource(info)
          )
        }
      )
    })
  }
}
module.exports = BuildTimePlugin
```

`thisCompilation` 与 `compilation` 的区别：前者在实例创建**之前**触发、可安全挂早期钩子；后者在其**之后**触发，适合读取已初始化状态。

## loader vs plugin 能力边界

| 维度 | loader | plugin |
| --- | --- | --- |
| 形态 | 函数（可挂 pitch 属性） | 类，`apply(compiler)` |
| 作用粒度 | 单个模块的内容 | 整个构建生命周期 |
| 核心能力 | 转换源码：TS→JS、CSS→JS、md→html | 事件订阅、产物增删改、扩展运行时、注入入口 |
| 能改模块解析吗 | 否（只处理已解析的内容） | 能（resolve 系列钩子） |
| 能新增产物文件吗 | 否（只能转换当前模块内容） | 能（`emitAsset`） |
| 配置位置 | `module.rules[].use` | `plugins[]`（实例数组） |
| 注册形态 | 函数/路径 + options | `new Plugin()` |
| 执行时机 | 模块构建阶段（make 内） | 任意钩子时刻 |

选择口诀：**改"一个文件的内容"用 loader，改"构建这件事本身"用 plugin**。

## 速查表

| 需求 | 方案 |
| --- | --- |
| 同步转换模块 | loader 直接 `return` 新内容 |
| 异步转换模块 | `this.async()` + `callback(null, code, map)` |
| 解析 loader 选项 | `this.getOptions()`（webpack5 内置） |
| 拦截整条链 | loader 的 `pitch` 返回非 undefined |
| 构建完成通知 | `compiler.hooks.done` / `afterEmit` |
| 增删改产物 | `compilation.hooks.processAssets`（带 stage） |
| 新增产物文件 | `compilation.emitAsset(name, new RawSource(code))` |
